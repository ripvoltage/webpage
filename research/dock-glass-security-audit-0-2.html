SECCIÓN 1: VEREDICTO

Las extensiones de GNOME Shell representan un componente crítico en la seguridad del entorno de escritorio Unix/Linux. A diferencia de las aplicaciones aisladas por sandbox (como Flatpak o Snap), las extensiones se ejecutan directamente dentro del mismo espacio de memoria y proceso del compositor (gnome-shell). En consecuencia, comparten todos los privilegios de la sesión del usuario: cualquier falla no controlada puede derribar la sesión gráfica por completo, y cualquier código malicioso podría ejecutar binarios arbitrarios, capturar pulsaciones de teclado, filtrar archivos personales o manipular ventanas.

Dock Glass (dock-glass@atarico.github.io) es una extensión de GNOME Shell diseñada para proporcionar efectos visuales avanzados inspirados en el dock de macOS sobre Ubuntu Dock y Dash to Dock: magnificación continua con dispersión proporcional de iconos, rebote de lanzamiento, efecto lámpara mágica (genie effect) al abrir ventanas y despliegue tipo abanico/cuadrícula de lugares para el explorador de archivos.

Evaluación General: La base de código de Dock Glass exhibe una postura de seguridad y estabilidad ejemplar. La superficie de ataque es mínima: no existen dependencias de red ni bibliotecas de telemetría (Soup, fetch o llamadas remotas); no se generan subprocesos arbitrarios del sistema (GLib.spawn_* o Gio.Subprocess); no existe uso de evaluación dinámica (eval o Function); el acceso al sistema de archivos es estrictamente de solo lectura y asíncrono para leer marcadores de usuario; y cada gancho sobre el gestor de composición cuenta con bloques de contención de excepciones para garantizar que un fallo visual nunca comprometa la estabilidad del entorno de escritorio.

SECCIÓN 3: ANÁLISIS EN PROFUNDIDAD DEL CÓDIGO FUENTE

1. Ausencia de Red y Confinamiento de Ejecución

El mayor riesgo en extensiones de terceros radica en la exfiltración silenciosa de datos o la ejecución de cargas útiles desde servidores externos. En Dock Glass, una inspección exhaustiva de todos los módulos confirma la ausencia absoluta de clientes HTTP, WebSockets o invocadores de subprocesos: 

// Búsqueda estricta de primitivas de red y procesos en todo el árbol de archivos:
// - gi://Soup: 0 coincidencias
// - fetch / XMLHttpRequest: 0 coincidencias
// - Gio.Subprocess / GLib.spawn_*: 0 coincidencias
// - eval / Function: 0 coincidencias

Por qué es seguro: La extensión opera como un conjunto estricto de actores gráficos y transformaciones visuales matemáticas en Clutter. La imposibilidad de abrir sockets o ejecutar procesos del sistema operativo garantiza que no puede ser utilizada como vector de comando y control (C2) ni como canal de persistencia.

2. Despacho Seguro de URIs y Lectura Asíncrona (`stack.js`)

La característica de "Stacks" permite desplegar accesos rápidos a carpetas del usuario. El módulo implementa una promesa dedicada para lectura asíncrona de marcadores GTK, evitando la modificación global de prototipos de GIO: 

// Desde stack.js (Líneas 46-66):
function openUri(uri) {
    try {
        Gio.AppInfo.launch_default_for_uri(uri, global.create_app_launch_context(0, -1));
    } catch (e) {
        console.error(`[dock-glass] Cannot open ${uri}: ${e}`);
    }
}

// Lectura sin bloquear el hilo principal de la shell ni alterar Gio._promisify
function loadContents(file) {
    return new Promise((resolve, reject) => {
        file.load_contents_async(null, (source, result) => {
            try {
                resolve(source.load_contents_finish(result)[1]);
            } catch (e) {
                reject(e);
            }
        });
    });
}

Por qué es seguro: Gio.AppInfo.launch_default_for_uri delega la apertura al manejador predeterminado configurado por el usuario en el entorno de escritorio (como Nautilus). No se ejecuta código shell arbitrario, y el uso de load_contents_async garantiza que un archivo de marcadores lento o bloqueado nunca congele la interfaz gráfica de GNOME.

3. Acoplamiento Dinámico Restringido por UUID (`dockAdapter.js`)

Para interactuar con Dash to Dock o Ubuntu Dock sin alterar su código en disco, la extensión carga dinámicamente el módulo docking.js correspondiente: 

// Desde dockAdapter.js (Líneas 14-28):
export const DOCK_UUIDS = ['dash-to-dock@micxgx.gmail.com', 'ubuntu-dock@ubuntu.com'];

export async function importDock(extensionManager, uuid) {
    const extension = extensionManager.lookup(uuid);
    if (!extension)
        return null;
    // Misma URI que la extensión del dock utiliza internamente
    return import(extension.dir.get_child('docking.js').get_uri());
}

Por qué es seguro: La importación está fuertemente restringida a la lista blanca DOCK_UUIDS. Solo se resuelven extensiones ya instaladas y registradas en el gestor de extensiones local de GNOME Shell. No se aceptan entradas externas ni URLs arbitrarias en la sentencia import().

4. Resiliencia del Bucle de Renderizado y Tolerancia a Fallos (`extension.js`)

Las rutinas de magnificación calculan el escalado en tiempo real durante eventos continuos del puntero. Un error no interceptado en un evento de cuadro (new-frame) provocaría errores masivos en el registro del sistema o la congelación del puntero: 

// Desde extension.js (Líneas 529-537):
_magnifyFrame(dock, magnifier) {
    // Un error aquí se repetiría cada cuadro; se registra una vez y se detiene
    try {
        this._magnifyStep(dock, magnifier);
    } catch (e) {
        console.error(`[dock-glass] Magnification failed: ${e}`);
        this._stopMagnifier(dock);
    }
}

Por qué es seguro: Al detectar cualquier anomalía, el temporizador de magnificación se desconecta de inmediato mediante _stopMagnifier(dock). Asimismo, el algoritmo valida explícitamente mediante Number.isFinite que coordenadas intermedias no sean NaN, evitando desbordamientos de cálculo geométrico en Clutter.

5. Interceptación No Destructiva del Gestor de Ventanas (`openAnimation.js`)

Para reproducir la animación de apertura de ventanas (Genie Effect), se intercepta la función interna Main.wm._shouldAnimateActor: 

// Desde openAnimation.js (Líneas 42-64):
const previous = Main.wm._shouldAnimateActor;
this._previous = previous;
this._wrapper = function (actor, types) {
    if (self._shouldTakeOver(actor)) {
        self._suppressed.add(actor);
        return false;
    }
    return previous.call(this, actor, types);
};
Main.wm._shouldAnimateActor = this._wrapper;

// Restauración ordenada al deshabilitar:
if (Main.wm._shouldAnimateActor === this._wrapper)
    Main.wm._shouldAnimateActor = this._previous;

Por qué es seguro: La cadena de interceptación respeta otras extensiones populares que envuelven el mismo método (como Burn My Windows o Magic Lamp Effect). Si la función fue envuelta por otra extensión posterior, no se rompe la cadena, actuando como un puente pasivo y desinstalándose limpiamente cuando se apaga.

SECCIÓN 4: PUNTOS DESTACADOS EN ARQUITECTURA Y RENDIMIENTO

La arquitectura de Dock Glass refleja prácticas de ingeniería de software avanzadas:

  • Separación de Lógica Pura y Actores Gráficos: Los módulos magnifier.js y stackLayout.js son funciones matemáticas puras (curva de campana coseno, dispersión parabólica, suavizado exponencial). Al no importar módulos de entorno gi://, son directamente testeables mediante frameworks de prueba en Node.js de manera aislada.
  • Compatibilidad Multi-Versión (GNOME 46 a 51): El módulo shellCompat.js abstrae las divergencias de la API de Clutter/St entre versiones sucesivas de GNOME (por ejemplo, el soporte transicional entre orientation y el atributo deprecado vertical, así como la verificación de captura de puntero en Clutter.GrabState).
  • Suavizado Asíncrono e Inercial: El cálculo de interpolación exponencial (approach) con constantes de tiempo calibradas evita tirones durante barridos rápidos del ratón, desactivando la ejecución del timeline cuando los iconos alcanzan el estado de reposo para minimizar el consumo de CPU.
SECCIÓN 5: RECOMENDACIONES PARA EL FUTURO
  1. Validación de Esquema en URIs de Marcadores: Al procesar las líneas de ~/.config/gtk-3.0/bookmarks en stack.js, implementar una validación explícita para restringir los esquemas permitidos (ej. file://, smb://, sftp://), descartando entradas anómalas antes de invocarlas con el manejador predeterminado.
  2. Pruebas Automatizadas de Composición: Integrar una suite de pruebas de integración continua (CI) en GitHub Actions utilizando entornos headless con Mutter/Mutter-test para verificar que las actualizaciones de GNOME Shell no alteren las llamadas privadas a Dash to Dock.
  3. Aislamiento ante Escalado Fraccionario: Probar explícitamente las coordenadas transformadas (get_transformed_position) en configuraciones multimonitor con factores de escalado Wayland fraccionarios mixtos (ej. 125% y 150%) para anticipar posibles desalineaciones visuales en clones de rebote.
